# Велометр

Личный веб-дневник велопробега с импортом данных из Strava. Показывает пройденное расстояние за год, недельную статистику и историю поездок. Приложение разворачивается на своём сервере и хранит данные в SQLite.

Интерфейс на русском языке. Для входа используется общий код доступа — без регистрации и отдельных аккаунтов. Данные обновляются вручную через ZIP-архив экспорта Strava.

## Основные возможности

- **Статистика за выбранный год:** общий пробег, количество поездок, средний недельный пробег и самая длинная поездка.
- **График пробега по неделям:** 52 столбца с подсветкой пиков и просмотром расстояния при наведении или нажатии.
- **История поездок:** название, дата, расстояние, продолжительность, средняя и максимальная скорость.
- **Импорт ZIP-архива Strava:** выбор файла или перетаскивание в окно импорта, отчёт о добавленных и пропущенных записях.
- **Защита от дублей:** уже загруженные активности пропускаются по идентификатору Strava.
- **Хранение треков:** файлы из архива, связанные с активностями, сохраняются в базе в сжатом виде.
- **Адаптивный интерфейс** для компьютера и телефона.

## Быстрый запуск

Понадобятся Git, Docker и Docker Compose v2. Java и Gradle на хосте для этого способа не нужны: сборка выполняется в контейнерах.

1. Клонируйте репозиторий и перейдите в его каталог:

   ```bash
   git clone <URL-этого-репозитория>
   cd velometr
   ```

2. Создайте файл настроек:

   ```bash
   cp .env.example .env
   ```

3. В `.env` замените `AUTH_PASSCODE=change-me` на свой код доступа. Остальные параметры можно оставить по умолчанию.

4. Соберите и запустите приложение:

   ```bash
   docker compose up -d --build
   ```

5. Откройте [http://localhost:8080](http://localhost:8080) и введите код из `AUTH_PASSCODE`.

Первая сборка загружает зависимости и компилирует Kotlin/Wasm, поэтому может занять несколько минут. При запуске на сервере вместо `localhost` используйте его адрес.

### Управление приложением

```bash
# Состояние контейнеров
docker compose ps

# Логи приложения
docker compose logs -f

# Остановка
docker compose down

# Пересборка и запуск после обновления исходников
docker compose up -d --build
```

После перезапуска backend потребуется снова ввести код доступа.

## Настройки

Все параметры описаны в [.env.example](.env.example). Локальный `.env` исключён из Git.

| Переменная | По умолчанию в примере | Назначение |
| --- | --- | --- |
| `AUTH_PASSCODE` | `change-me` | Общий код доступа. Задайте своё непустое значение. |
| `DATA_PATH` | `/data/velometr.db` | Путь к SQLite. В Docker это путь внутри контейнера backend. |
| `DATA_VOLUME` | `velometr-data` | Docker volume для каталога `/data`. Можно указать абсолютный путь к каталогу на хосте. |
| `FRONTEND_PORT` | `8080` | Порт, на котором Docker Compose публикует приложение. |
| `FRONTEND_BUILD_MODE` | `production` | Режим сборки интерфейса: `production` или `development`. |
| `PORT` | `8080` | Порт backend при запуске напрямую. В Docker Compose эта переменная не используется. |

Для смены внешнего порта задайте, например, `FRONTEND_PORT=8090`, затем повторите `docker compose up -d`. Приложение будет доступно по адресу `http://localhost:8090`.

### Хранение данных

По умолчанию база хранится в Docker volume `velometr-data` и сохраняется после пересборки контейнеров и команды `docker compose down`. Команда `docker compose down -v` удаляет этот volume вместе с данными.

Чтобы хранить базу в выбранном каталоге на сервере, задайте в `.env`:

```dotenv
DATA_VOLUME=/srv/velometr/data
DATA_PATH=/data/velometr.db
```

Тогда файл базы на хосте будет находиться по пути `/srv/velometr/data/velometr.db`. Смена `DATA_VOLUME` не переносит существующие данные автоматически.

## Импорт данных

1. Подготовьте ZIP-архив полного экспорта своих данных Strava, содержащий `activities.csv`.
2. Войдите в Велометр и нажмите **«Импорт данных»**.
3. Перетащите ZIP в окно импорта или выберите его через диалог файлов.
4. Подтвердите импорт и дождитесь результата.
5. Выберите год, за который хотите посмотреть статистику.

Лимит загрузки — 500 МиБ; при запуске через nginx в этот лимит входит весь HTTP-запрос. Архив распаковывать заранее не нужно. Для обновления истории загрузите новый экспорт: новые активности добавятся, существующие будут пропущены. Повторный импорт не обновляет ранее сохранённые записи.

Расстояние, время и скорость берутся из CSV, а не рассчитываются по точкам трека. Отсутствие файла трека не мешает импорту активности.

### Особенности текущей версии

- Импортируются все активности из CSV, без фильтрации по виду спорта. Если экспорт содержит бег или другие занятия, они тоже попадут в статистику.
- Треки сохраняются, но просмотр маршрутов на карте и отдельный экран поездки пока не реализованы.
- Недельный график использует 52 периода от начала года: по семь дней, с оставшимися днями в последнем периоде. Средний недельный пробег равен годовому пробегу, делённому на 52.

## Разработка

Стек: **Kotlin 2.4.20**, **Ktor 3.1.3**, **Compose Multiplatform 1.12.0 / Kotlin/Wasm**, **SQLite**, **nginx**. Gradle Wrapper 8.14.4 включён в репозиторий.

### Через Docker Compose

Для ускоренной локальной сборки интерфейса задайте в `.env`:

```dotenv
FRONTEND_BUILD_MODE=development
```

Затем выполните `docker compose up -d --build`. Этот режим пропускает оптимизации Kotlin/Wasm и минификацию. Для развёртывания используйте `production`.

BuildKit сохраняет зависимости Gradle, историю задач и промежуточные результаты между Docker-сборками. Команда `docker compose up -d --build` остаётся прежней: первая сборка заполняет кеши, последующие используют их при пересборке изменённых исходников. Backend и frontend используют отдельные кеши. Локальная сборка без Docker с ними не связана.

Кеши принадлежат Docker builder и не входят в итоговые образы. `docker compose down` их не удаляет; очистка кешей builder или автоматическая сборка мусора может удалить их, после чего сборка заполнит их заново. Production-оптимизация Kotlin/Wasm и webpack может оставаться затратной даже с прогретыми кешами.

### Backend без Docker

Понадобится JDK 21. Команды ниже предназначены для Bash и запускаются из корня проекта:

```bash
mkdir -p .local
DATA_PATH="$PWD/.local/velometr.db" \
AUTH_PASSCODE='your-local-passcode' \
PORT=8080 \
./gradlew :backend:run
```

При прямом запуске `.env` автоматически не загружается. База и таблицы создаются при старте. Каталог `.local` с личными данными не добавляйте в коммиты.

Проверка доступности backend:

```bash
curl http://localhost:8080/health
```

### Сборка интерфейса и тесты

```bash
# Тесты backend
./gradlew :backend:test

# Сборка интерфейса для развёртывания
./gradlew :frontend:wasmJsBrowserDistribution
```

Готовые файлы интерфейса появятся в `frontend/build/dist/wasmJs/productionExecutable/`.

Интерфейс обращается к `/api/` на том же адресе, с которого открыта страница. В Docker Compose проксирование настроено в [frontend/nginx.conf](frontend/nginx.conf). При отдельном запуске интерфейса и backend понадобится аналогичный reverse proxy: один только dev-сервер frontend на порту `8081` запросы к API не перенаправляет.

```text
openspec/            Спецификации и архив изменений
docker-compose.yml   Запуск backend и frontend
.env.example         Пример настроек
```
